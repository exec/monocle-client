# 0.7.29 crew rejoin and prediction waits

The live job was inspected read-only; no job controls or host restart were issued while preparing this patch.

Unbans was connected and off duty, showing “Waiting for the host to restore this worker's lane.” Its reported work row was 802 while its physical position was around row 958, twenty blocks behind the two active workers at row 978. Readiness depended on the old job world and old work-position chunks, creating a circular lane-restoration wait after reconnect. The existing availability transition also required a crew-wide regroup.

The patch refreshes off-duty world readiness using the current loaded chunk, preserves the original server/dimension/player boundary and supply recovery, and reuses revisioned incremental service updates for manual leave/rejoin. Returners approach live rendered crewmates through the existing flight/running controller before joining the active work window. Peers retain their execution, generation, work position and outstanding ACKs. Disconnected off-duty workers no longer pause the whole crew.

Returning bots reconstruct underfoot and two trailing paving rows, plus a verification blocker within five rows behind, even without local paving history. Manual world/inventory interaction is no longer guarded by a disabled or off-duty builder.

Additional user observations: ghost placements sometimes waited a long time before resolving, and boats could block work. Pending placements now have independent ages and trigger a sequenced probe after four ticks, rate-limited to one per four ticks. An empty/totem offhand requests correction without aborting mining; otherwise the existing non-mining ABORT probe is used. Probes never count as server confirmation. Boats intersecting the current work/walking/supply placement area are attacked with cooldown and normal rotation settings; unrelated boats and the worker's own vehicle are excluded.

Validation includes executable world-readiness, repair-window, placement-age, boat-target and manual-action policies; incremental revision/reordering checks; and real host/worker socket tests for manual leave/rejoin while another worker progresses without a generation/workflow restart. Minecraft/server behavior still needs live testing. Both the shared-core host and worker clients need updating for the new availability messages.
