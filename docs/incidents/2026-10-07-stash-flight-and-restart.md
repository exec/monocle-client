# Stash flight, restart and cancellation recovery

A terminal host failure can still leave a worker's uncertain inventory checkpoint owning cleanup. Explicit cancellation retries must reopen that cleanup debt without losing failure evidence. Acknowledged cancellation does not prove an uncertain move succeeded.

Hopper-refilled pickup sources require proof in a server-confirmed previously empty player slot; an identical refilled source does not invalidate that gain. Ordinary sources retain source-change verification. Interaction routes use actual body clearance rather than printer placement clearance and retain bounded escape/landing retries.

Disconnect or restore invalidates stale home-arrival flags while preserving inventory checkpoints. Check current location first, then retry an unobserved teleport within persisted warmup, timeout and attempt limits. Do not resend an already completed arrival.

Deploy standalone hosts into immutable versioned runtimes. Rebuilding installDist in a running process's classpath can remove lazily loaded web resources without stopping the JVM. Launcher replay must not depend on vanished temporary agents or an expired launcher RPC session. These are separate failure modes; successful recovery of one does not validate all others.
