# Stash columns and kits

Save a stash definition with its `/home` name and cuboid even if you do not scan it. In Stash Manager, **Column Map** opens only the bottom chest layer. Its contents identify each column; upper chests are assumed to contain the same kind of stock, but their quantities are unknown. **Full** scans the cuboid and retains the existing optional Lazy Mode estimates. Only directly observed shulkers contribute to exact kit counts.

Shulker color (item ID) plus custom name defines a stable **Shulker Type ID**. The fullest contents observed for that type become its exemplar. A box missing any exemplar item or quantity is counted as incomplete. Copy the ID from the stash card; rechecking a chest can update the exemplar and counts. Older saved observations are indexed on load.

The built-in **Kit Delivery** and **Remove Incomplete Kits** workflows use one worker per job. Supply a source stash, Shulker Type ID, and count (1–36). A destination can be a player (exact UUID and username, who must accept `/tpa`), a nearby ender chest, another defined stash in the same world, or the worker's carried inventory. Incomplete removal defaults to carried inventory; select a separate destination stash to quarantine those boxes. The worker first takes boxes observed in the scan, then searches unscanned upper chests in mapped columns as needed. An unscanned column is a search hint, not a stock guarantee.

**Transfer all** is available for stash-to-stash jobs on workers running 0.13.17 or newer. Enable it in the WebUI kit job form or in-game host task editor; the count becomes the per-trip cap (up to **36**). The equivalent workflow arguments are `transferAll: true`, `count: 36`, `destination: "Stash"`, and `targetStashName`. `includeIncomplete: true` optionally includes incomplete boxes of the same type. Incomplete-removal jobs cannot include complete boxes.

Repeat transfers require a **Full** source scan with Lazy Mode off and no inferred/unknown container records. On 0.13.26, a known location invalidated by our own confirmed withdrawal can be searched again without pretending its quantity is still current. They check every selected matching source container live, revisiting it until empty before advancing; hoppers and other scanned storage containers are supported. Updated built-in workflows revisit sources after productive passes, then require two empty passes separated by 20 ticks before finishing. This catches hopper-fed refills of previously visited chests; it is not a transaction-wide snapshot against concurrent players. Newly added stock in other columns requires a new scan/job. Selections exceeding 54 selected source containers or the 24,000-character prepared-action bound are rejected, never silently truncated. Source and destination cuboids must not overlap. A missing, blocked, or unresponsive source container is not treated as empty: bounded retries report the actual target/block, and an already-confirmed partial stash load is deposited before the workflow reports failure. An uncertain inventory click still requires inspection; it is never replayed. Concurrent jobs against the same source stock are unsupported. Update either host mode to obtain the revised built-in script; existing jobs retain their own workflow snapshots.

Kit jobs withdraw at most the worker's currently free inventory slots, complete that delivery/deposit, then return for the next batch. The source cursor and remaining count are checkpointed, and each move is server-confirmed before it counts. No existing inventory is dumped. **Carry** cannot batch because it has nowhere to empty the first load, so it requires enough free slots for the whole request. Move any already-carried boxes of the same kit type out of inventory before starting so they cannot be mistaken for the job's boxes.

Opening a stash container does not require a pickaxe or an empty inventory/hotbar slot. Scanning and depositing work with a full inventory; withdrawing still needs space for the requested boxes. The opener verifies that a container is still present and uses a normal non-sneaking click without rearranging the inventory. Pickup retains the server's shift-click slot order, which may fill the hotbar first.

The standalone host's **Stashes** page shows observed kit types and complete/incomplete counts. Use **Deliver** or **Remove incomplete** to open the guided job preview: select one worker, count, destination, and (for player delivery) the exact username and UUID. The usage panel counts only retained jobs; new completed jobs report actual delivered boxes, not the repeat-job batch cap. Partial transfers from failed or cancelled work are not included.

On **0.13.25 or newer**, destination deposits keep the menu open and place each kit in an explicitly selected empty slot. Two ordered clicks request immediate authoritative post-click snapshots without local prediction. The pickup snapshot (kit on cursor) is not a deposit receipt; placement requires the exact kit/quantity in the chosen slot, an empty cursor, and one fewer carried kit. A subsequently running hopper may move a verified kit onward without invalidating its receipt. No delayed batch reopen is required. A changed menu cannot acknowledge an unfinished move, and restarting an uncertain move requires inspection rather than replaying it.

**Destination columns** require host and worker **0.13.18 or newer**. The shared host catalog reserves each column for one exact Shulker Type ID across jobs and restarts. Existing matching-kit columns are preferred, followed by already-reserved empty columns, then newly observed empty columns. An empty observed bottom chest is a candidate, not proof that all upper chests are empty. Unknown columns and loose/mixed contents are never treated as free space. Reservations and free/conflict counts appear in stash inspection and the WebUI.

Workers open and report each destination chest before depositing. The host acknowledges the live contents before authorizing moves. Different or mixed contents update the catalog, reassign/block the old column as appropriate, and redirect that worker to another eligible column. A full column is skipped for the current job while retaining its kit ownership. Vertical columns and 1:1 diagonal stacks behind a bottom chest row are supported; irregular layouts should be defined separately. Exhausting observed suitable columns fails explicitly without mixing kits. Use one destination definition for each physical storage area; concurrent jobs or overlapping writable definitions targeting the same physical columns are unsupported.

Transfers stop for inspection if a click is not server-confirmed. Confirmed source withdrawals invalidate affected source catalog records; rescan them for current quantities. Reserved destination deposits report observed contents again at chest/batch boundaries, retaining those observations even when a late status receipt arrives. These are point-in-time observations: hopper buffers and later transfers are not included in an exact chest count until scanned. Legacy workers invalidate deposit records until rescanned. Do not schedule concurrent kit jobs against the same boxes.

Worker workflows can retain controlled flight between nearby stash scan, withdrawal, and deposit actions, including through nested workflow calls. The flight handoff requires the next stash in the same dimension and within 32 blocks of the worker. Separately, on 0.13.26 a stash within 256 blocks is reached locally without issuing `/home`; withdrawals measure to the selected source container when available, other actions measure to the cuboid. The target chunk need not already be loaded: local navigation can approach it, and source waits require useful progress. More distant actions honor home warmups/cooldowns. Navigation can still land when needed; teleports, profile changes, cancellation, and workflow completion retain safe landing checks. Solo scans retain their existing land-on-completion behavior.

Scan approach watchdogs require a new closest approach of at least 0.25 blocks to count as useful progress. Oscillation or walking away does not renew the ten-second timeout. Failed approaches remain recorded as unscanned containers, not assumed contents; telemetry exposes `noProgressTicks` and `closestOpeningDistance` for diagnosis.

On 0.13.27, stash takeoff and flight use the real player footprint. Standing flush against the side of a chest is not an overhead obstruction; actual ceiling collisions and loaded-world hazard checks still gate flight. This applies to scans, withdrawals and deposits through their shared stash movement path.

## Queued flight preference (not implemented)

- The **256-block** local `/home` bypass is implemented in 0.13.26. Destination deposits still use cuboid proximity until the host assigns a column; refining that to an actual approach target remains follow-up work.
- Prefer configured Elytra Fly for local trips over **64 blocks** when usable gear and a safe route are available; otherwise use existing walking/Baritone navigation. Short trips remain local ground navigation. Do not add a second flight speed/acceleration configuration.
- Check repeated stash-to-stash deliveries, source returns, same-home transfers, elevated chests, missing/broken elytra, and unloaded or blocked routes. Keep the **64-block flight preference** queued until the source/deposit recovery changes have been live-tested.
